Code Analysis — Competition 2

室友解法分析

本文分析 cite/competition_2_moving_ego_mot_student/ 中的追蹤器實作。 該解法以純距離匹配 + 速度外插取代 Kalman Filter，在 seq_4 的 moving-ego 情境下一次通過 baseline。

整體架構

程式碼共三個核心檔案，分工明確：

偵測提取（Detection Extraction）

calculate_cluster_centroids() 對每個移動群集計算：

  • 空間中心：所有點的 平均 [x, y, z]
  • 速度特徵：所有點的 平均 range_rate (ṙ)

build_detections() 將結果組成形狀 (N, 5) 的陣列，格式為 [x, y, z, cluster_id, range_rate]，直接傳入 tracker。

Track 預測（Motion Model）

本解法不使用 Kalman Filter，改以直接的速度外插（velocity extrapolation）： 

# 每次配對前，對未配對的 track 進行位置外插
track["mean"] += track["velocity"] * max(track["age"], 1)

# 配對後，以當前偵測更新位置與速度
track["velocity"] = current_mean - previous_mean  # Δpos / 1 frame

速度 = 前後幀的位置差，等同於假設每個物體做常速直線運動（CV）且取樣間隔為 1 幀。 對 age > 1 的未配對 track，速度會被乘以累積幀數，相當於線性外插至該幀的預期位置。

缺點：速度估計沒有雜訊濾波，若單幀偵測位置跳動較大，速度估計就會不穩定。 Kalman Filter 在這個環節提供了平滑效果（process noise vs. measurement noise 的 trade-off）， 但對 seq_4 的相對直行車流而言，單幀的位置誤差不大，粗略外插已足夠。

資料關聯策略（Data Association）

代價函數

每對 (track i, detection j) 的代價為：

xy_dist  = || pos_i[:2] - det_j[:2] ||   # XY 平面歐氏距離
z_dist   = | pos_i[2]  - det_j[2]  |    # 高度差（絕對值）
rr_dist  = | rr_i      - rr_j      |    # Range rate 差

cost = xy_dist + 0.1 * z_dist + 0.05 * rr_dist

三個特徵的權重差距懸殊：z_dist 只佔 10%，rr_dist 只佔 5%， 代價矩陣在實務上幾乎等同於純 XY 平面距離。 z 和 range_rate 僅在距離相近時起到微弱的決勝作用。

特徵權重物理意義實際影響
xy_dist 1.0 水平面位置差 主導
z_dist 0.1 雷達高度差（同車輛類型差異小） 微弱
rr_dist 0.05 Doppler 速度差（1 m/s 量化） 極微弱

閘門（Gating）

只使用硬性歐氏距離閘門：若 xy_dist > max_distance (5.0 m) 則直接跳過，不填入代價矩陣。閘門設計非常寬鬆，不使用 Mahalanobis 距離。

指派演算法

使用 scipy.optimize.linear_sum_assignment（Hungarian algorithm）進行全域最優指派。 指派完成後，再過濾掉代價超過閾值的配對。

Track 生命週期（Track Lifecycle）

參數值說明
max_age 5 未配對超過 5 幀後刪除 track
min_hits 1 命中 1 次即為 confirmed，等同於沒有 tentative 階段
max_distance 5.0 m XY 閘門半徑

min_hits=1 是關鍵設計：新出現的物體在第一幀就被確認並輸出 track_id， 無需等待暖機期。對 seq_4 這種目標始終可見、遮擋少的場景，這降低了早期 FN（false negative）。

輸出過濾邏輯：只輸出「已確認 且 本幀有配對到偵測」的 track。 未配對但仍存活的 track（在 max_age 內）不會出現在本幀的 cluster_track_dict 中。 這使輸出更保守，減少幽靈 track 造成的 FP。

Ego 運動處理

Competition 2 明確提供 ego_global_pos.txt，題目說明中也建議設計 ego-motion compensation。 該解法在 main.py 中確實載入了 ego 位置： 

ego_pos_list = ego_pos_distance(seq_dir / "ego_global_pos.txt")

然而在關聯步驟中，ego 資訊完全未被使用： 

# Association does NOT use ego pose — all detections are in radar (ego) frame
confirmed_tracks = tracker.update(detections)

這意味著 KF 的 predict 步驟沒有考慮 ego 移動，追蹤完全在 radar（ego）座標系下進行。 能夠通過 baseline 的原因可能是：

  • seq_4 幾乎全程直行，ego 速度方向穩定，座標系偏移相對可預測
  • 5.0 m 的寬鬆閘門足以容納單幀內 ego 移動造成的位置偏差
  • 速度外插 pos += vel·age 在直行場景下能部分補償 ego 移動（因為前景車輛的偵測位置變化包含了 ego 速度分量）
風險：若 ego 有明顯轉彎或加速，radar frame 下的物體座標會快速偏移， 5.0 m 閘門可能不足以吸收，導致 track 斷裂（IDSW 上升）。

評估指標（MOTA Proxy）

評估函數 evaluate_tracking.py 實作了 MOTA（Multi-Object Tracking Accuracy）的近似版： 

MOTA_proxy = 1 - (FP_points + FN_points + IDSW_proxy) / GT_positive_points

MOTA 的三個懲罰項目含義如下：

指標說明
FP_points GT 為 static/unknown，但 pred 給出 track_id 的點數
FN_points GT 為 moving（有 track_id），但 pred 無輸出的點數
IDSW_proxy 同一 GT track 在前後幀被指派到不同 pred track_id（身份切換）

評估單位是雷達點而非物體框（bounding box），因此群集較大的物體對分數影響也較大。

為何能通過 Baseline

seq_4 的場景特性讓簡單解法得以成立：

  • 直行主導：ego 和周遭車輛都近似直行，無複雜機動，速度外插的誤差較小
  • 目標稀疏：同向車流目標數量有限，Hungarian 指派的歧義性低
  • 群集穩定：4D 雷達群集在連續幀之間位置跳動不大（無 ego 補償的誤差在閾值內）
  • 寬鬆閘門：5.0 m 覆蓋了 ego 移動和量測雜訊的綜合偏差
  • 立即確認：min_hits=1 減少早期 FN，在 seq_4 的簡單場景下 FP 不多
核心洞察：在特定場景下，選對閘門閾值與代價函數的量級 比使用複雜運動模型更重要。室友解法的 5.0 m 閘門和 min_hits=1 是最關鍵的兩個參數選擇。 Kalman Filter 的優勢在於對機動目標和 ego 轉彎的處理——在 seq_4 這種單純場景下， 優勢並不顯著。
