隊友追蹤方法說明

本文說明隊友針對 Competition 1（靜態自車 4D Radar MOT） 實作的追蹤方案。 核心為等速 Kalman Filter（KF）＋ 融合距離、Range Rate、RCS 的 Hungarian 配對， 並以 Graveyard Re-ID 機制回收已刪除 Track 的 ID，降低 ID-Switch。 程式碼位於 cite/teammate/competition_1_static_mot_student/starter_code/。

整體流程

運動模型：等速 Kalman Filter（KalmanTrack）

每個 Track 維護一個獨立的 CV（Constant Velocity）KF，狀態向量定義在 XY 平面：

向量維度內容
狀態 \(\mathbf{x}\) 4 × 1 \([x,\; y,\; v_x,\; v_y]^\top\)；新建 Track 速度初始化為 \([0, 0]\)
觀測 \(\mathbf{z}\) 2 × 1 \([x,\; y]^\top\)（僅位置；無 range rate 觀測）

系統矩陣（dt = 0.1 s）：

\[ \mathbf{F} = \begin{bmatrix} 1 & 0 & dt & 0 \\ 0 & 1 & 0 & dt \\ 0 & 0 & 1 & 0 \\ 0 & 0 & 0 & 1 \end{bmatrix}, \qquad \mathbf{Q} = \operatorname{diag}\!\bigl(0.5\,dt^2,\; 0.5\,dt^2,\; 2\,dt,\; 2\,dt\bigr) \] \[ \mathbf{H} = \begin{bmatrix} 1 & 0 & 0 & 0 \\ 0 & 1 & 0 & 0 \end{bmatrix}, \qquad \mathbf{R} = \operatorname{diag}(1,\; 1), \qquad \mathbf{P}_0 = \operatorname{diag}(2,\; 2,\; 5,\; 5) \]

過程噪聲 \(\mathbf{Q}\) 以 \(dt\) 縮放，反映加速度雜訊對位置（\(\propto dt^2\)）與速度（\(\propto dt\)）的影響。 初始速度協方差設為 5，是位置協方差（2）的 2.5 倍，反映速度初始不確定性較高。

KF 的 Predict / Update 採用標準線性卡爾曼公式：

predict:
  x̂ = F @ x
  P = F @ P @ Fᵀ + Q

update (given detection z = [x, y]):
  S = H @ P @ Hᵀ + R
  K = P @ Hᵀ @ S⁻¹
  x = x + K @ (z − H @ x)
  P = (I − K @ H) @ P
與本組方法的差異：本組 KF 觀測向量為 \([x, y, \dot{r}]\)（增廣 range rate）， 利用都卜勒速度加速速度收斂；隊友僅觀測位置 \([x, y]\)，速度完全靠位置差推算。 兩者各有取捨——增廣觀測收斂快但實作較複雜；純位置觀測更簡潔、對 RCS 不均勻場景更穩健。

代價函數與 Hungarian 配對

代價函數

對每個 (Track \(i\), Detection \(j\)) pair，代價由三項相加：

\[ c(i, j) \;=\; \underbrace{\|\hat{\mathbf{x}}_i - \mathbf{d}_j\|_2}_{\text{空間距離}} \;+\; \underbrace{w_{rr}\,\bigl|\dot{r}_i - \dot{r}_j\bigr|}_{\text{Range Rate 項}} \;+\; \underbrace{w_{rcs}\,\bigl|\text{RCS}_i - \text{RCS}_j\bigr|}_{\text{RCS 項}} \]

其中 \(\hat{\mathbf{x}}_i \in \mathbb{R}^2\) 為 Track \(i\) 的 KF 預測位置， \(\mathbf{d}_j\) 為 Detection \(j\) 的 cluster centroid。 若空間距離超過 max_distance，代價直接設為 \(10^9\)（硬閘門）。

RCS 項是隊友方案的特色。RCS（Radar Cross Section）反映物件的雷達反射強度， 同種類車輛的 RCS 具備跨幀一致性，可輔助區分密集場景中位置相近的不同目標。 本組代價函數尚未納入 RCS，這是可借鑑的改進方向。

Hungarian 分配

代價矩陣建立後，呼叫 scipy.optimize.linear_sum_assignment() 求全域最優一對一分配。分配後再次過濾：距離仍超過 max_distance 的 pair 視為未匹配， 防止強制分配到閘門外的目標。 

gated[dist_xy > max_distance] = 1e9
row_idx, col_idx = linear_sum_assignment(gated)

for r, c in zip(row_idx, col_idx):
    if dist_xy[r, c] <= max_distance:
        matched.append((track_indices[r], det_indices[c]))

Track 生命週期管理

每個 Track 經歷三個狀態：

狀態條件說明
tentative hits < min_hits 新建 Track，尚未確認為真實物件；不輸出至 result.csv
confirmed hits ≥ min_hits 已確認為追蹤目標；當幀有匹配（age = 0）時輸出至 result.csv
deleted age > max_age 連續未匹配超過閾值，移入 Graveyard

關鍵設計：確認 Track 在未匹配的幀（age > 0）不輸出到 result.csv， 即使 Track 仍存活。原因是每幀的 cluster_id 從 0 重新編號，未匹配幀儲存的舊 cluster_id 可能與本幀的不同物件衝突，輸出會造成 ID-Switch。 

for track in self.tracks:
    if track.track_state != "confirmed":
        continue
    if track.age > 0:
        continue    # 避免舊 cluster_id 與本幀衝突
    confirmed_tracks.append([x, y, z, cluster_id, track_id])

Graveyard Re-ID

刪除的 Track 不立即丟棄，而是存入 Graveyard 緩衝區， 保留其最後一次真實量測位置（last_measured_xy，非 KF 漂移後的預測位置）。 當新 Detection 出現時，先查詢 Graveyard，若距離小於 max_distance 則回收舊 ID。 

# 刪除 → 加入 Graveyard（儲存最後量測位置，非 KF 漂移位置）
self._graveyard.append({
    "xy":         track.last_measured_xy,  # 真實量測，不受 KF 漂移影響
    "range_rate": track.range_rate,
    "track_id":   track.track_id,
    "dead_for":   0,
})

# 新建 Track 時先查詢 Graveyard
def _match_graveyard(self, detection):
    for entry in self._graveyard:
        d = np.linalg.norm(entry["xy"] - detection[:2])
        if d < self.max_distance:
            self._graveyard.remove(entry)  # 消耗後不重複使用
            return entry["track_id"]
    return None  # 無匹配 → 分配新 ID

Graveyard 中的條目在 dead_for 超過 graveyard_age = max_age 幀後自動過期。 已被回收的條目立即從 Graveyard 移除（consumed），防止同一舊 ID 被多個新 Track 搶佔。

與本組的 Re-ID 進度對照： 隊友已實作 Position-only Graveyard Re-ID（對應本組「場景 ③」）。 本組因場景 ③ 難度較高（需外觀相似度比對），目前尚未實作。 隊友方案的限制：純距離閘門在物件密集場景可能將不同物件的 Re-ID 錯誤配對； 外觀（SAM2 mask 特徵）輔助可提高可靠性。
