## 整體 SLAM 流程

min_loop_interval: 閉環冷卻機制。避免系統在短時間內連續不斷地觸發與計算閉環。
min_interval: 歷史軌跡排除機制。避免將時間上極為接近的連續幀（單純的里程計推進）誤判為閉環事件。

- `_passes_correction_gate` 的驗證門檻：
    - np.linalg.norm(trans): 檢查總平移距離。若位移過大，代表匹配點可能飄移到遠方。
    - abs(trans[2]): 檢查 Z 軸（垂直）平移。自駕車行駛於路面，Z 軸變動過大代表不合理的「飛起或遁地」。
    - max(abs(roll), abs(pitch)): 檢查側傾角 (Roll) 與俯仰角 (Pitch)。限制車體不該出現極端的傾斜或翻轉變換。
    - 只要有任一項超過設定門檻，即判定此閉環匹配無效。

**每一幀 LiDAR 資料進來後：**

1. **ICP 對齊** — 當前幀對齊子地圖，更新 Odometry 位姿
2. **新增關鍵幀** — 儲存點雲與位姿至 `LoopClosure`
3. **觸發偵測** — 每隔 `detect_interval = 5` 幀執行一次迴圈偵測
4. **候選篩選** — `find_candidates` 找出空間鄰近且時間充分間隔的幀
5. **ICP 驗證** — `match` 對候選幀執行雙向 ICP 並驗證一致性
6. **位姿圖優化（PGO）** — 偵測成功時，以 `T_loop` 作為約束進行全局優化
7. **同步位姿** — `update_poses` 將優化後的位姿同步回 `LoopClosure`

僅對 Mask 指定區域計算誤差，並動態正規化，確保誤差權重不受遮罩面積大小影響。

pred: 模型預測輸出（例如：3DGS 渲染出的 2D 影像）
target: 真實目標值（例如：Ground Truth 參考照片


- L_1(depth)
    - 純影像驅動的 3DGS 容易產生「符合訓練視角，但實際幾何扁平破碎」的假象（Billboard effect）。強制計算渲染深度與 LiDAR 點雲的誤差，能約束高斯球體貼合真實物理空間，確保在各種視角下維持正確的三維結構。
    - 優化器為了走捷徑，可能會在相機前方直接生成像「2D 圖片或紙板」一樣的扁平高斯球體來拼湊畫面。
    - 結果就是：在訓練過的相機角度看過去非常逼真；但若移動相機切換到全新的視角 (Novel view) 觀察，就會發現這些物體根本沒有真實的 3D 結構，只是浮在空中的破碎平面。
    - 因此需要加入 LiDAR 深度資訊，強制約束這些高斯球必須生成在正確的三維空間座標上。
